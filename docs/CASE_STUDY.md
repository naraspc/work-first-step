# 프로젝트 기록

## 문제와 목표

지시받은 업무를 바로 시작하다 보면 담당 범위, 반드시 지킬 사항, 제출 기한을 잘못 이해한 채 작업할 수 있습니다. 목표는 받은 지시를 다시 확인할 수 있는 짧은 문서로 정리하는 것입니다. 특정 직종의 정답이나 승인 여부를 자동 판단하지 않습니다.

## 정보 구조

| 항목 | 역할 |
|---|---|
| 목적 | 왜 필요한 업무인지 |
| 담당 범위 | 어디까지 맡았는지 |
| 지킬 사항 | 유지해야 할 내용과 제한 |
| 구체적인 할 일 | 실제로 수행할 작업 목록 |
| 결과물·기한 | 무엇을 언제까지 마쳐야 하는지 |
| 확인 질문 | 아직 결정되지 않은 사항 |
| 진행 순서 | 할 일을 어떤 순서로 실행할지 |
| 변경 내용 | 처음 지시에서 달라진 점 |

## 피드백으로 바꾼 부분

- “내 말로 적기”를 “받은 업무 내용을 짧게 정리하기”로 바꿔 행동을 구체화했습니다.
- 다섯 항목이었던 예시를 실제 양식과 같은 여덟 항목으로 맞췄습니다.
- 작업 권한을 묻던 질문을 수행할 업무를 묻는 질문으로 바꿨습니다. 변경 권한의 불확실성은 확인 질문으로 이동했습니다.
- 예시의 작업 계획을 지시받은 사실처럼 보이지 않도록 표시했습니다.

## 데이터 보존

이전 버전의 `flex` 값은 변경 가능한 항목을 뜻했습니다. 새 양식에서는 같은 위치가 구체적인 할 일을 뜻합니다. 이전 형식(version 1)을 불러오면 해당 텍스트를 확인 질문에 보존하고 새 4번은 비웁니다. 점검표도 다시 검토하도록 초기화합니다. 새 저장 형식은 version 2입니다.

## 검증과 한계

Node.js 기반 검사로 예시/양식 순서 일치, 저장 파일 형식, 텍스트 내보내기, 이전 형식 데이터 이전, 잘못된 입력 처리를 확인합니다. DOM 대역을 이용하는 로직 검사이므로 실제 브라우저의 화면 배치, 파일 다운로드 UI, localStorage 권한 동작을 모두 보장하지 않습니다. 현재 실행 환경에서는 브라우저 QA를 수행하지 못했습니다.

계정·서버 동기화·공유 편집은 제공하지 않습니다. 임시저장은 백업을 대신하지 않습니다. 공개 이용에 따른 실제 효과는 아직 측정하지 않았습니다.

## 담당 및 도구 사용

문제 정의, 사용 맥락 제시, 문구와 질문 방향의 검토는 프로젝트 소유자의 피드백을 바탕으로 진행했습니다. AI 도구를 구현·예시 작성·문서화·검증 보조에 활용했습니다. 공개 포트폴리오에는 실제 수행 범위와 검증된 사실을 기준으로 설명합니다.
