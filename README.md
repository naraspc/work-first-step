# 업무 첫걸음

[GitHub Pages 서비스 주소](https://naraspc.github.io/work-first-step/) · [GitHub 저장소](https://github.com/naraspc/work-first-step)

받은 업무를 정리하고, 확인할 내용과 먼저 할 일을 찾아보는 무료 업무지시 정의서 도구입니다.

## 해결하려는 문제

업무 지시를 듣고도 목적, 담당 범위, 구체적인 작업과 마감 기준을 구분하기 어려운 순간이 있습니다. 업무 첫걸음은 여덟 가지 질문으로 지시를 구조화하고, 확인받은 사실과 자신의 계획을 구분하도록 돕습니다.

## 주요 기능

- 목적 → 담당 범위 → 지킬 사항 → 할 일 → 결과물·기한 → 확인 질문 → 진행 순서 → 변경 내용
- 같은 질문과 순서로 작성한 6개 직종의 예시
- 브라우저 임시저장, 메모장용 UTF-8 텍스트 내보내기
- JSON 백업·복원과 이전 양식의 의미 변경을 고려한 데이터 이전
- 계정 가입과 별도 서버 없이 사용하는 반응형 페이지

## 실행

`dist/index.html`을 브라우저로 열거나 다음 명령으로 로컬 서버를 실행합니다.

```sh
python3 -m http.server 8000 --directory dist
```

브라우저에서 http://localhost:8000 을 엽니다. 설치할 프런트엔드 의존성이나 빌드 단계가 없습니다.

```sh
node --test tests/app.test.cjs
```

## 기술과 설계

HTML, CSS, JavaScript, Web Storage, Blob 기반 다운로드를 사용합니다. 현재 규모와 회원가입 없는 이용 흐름에 맞춰 프레임워크·API·DB 없이 구현했습니다. 제공 예시와 작성 항목의 일치, 저장 데이터 보존이 핵심 검증 대상입니다.

입력 내용을 외부 API에 전송하는 코드, 분석 SDK, 외부 폰트는 포함하지 않습니다. 호스팅 사업자의 일반 접속 기록과 이용자가 직접 여는 참고 링크는 별개입니다. 임시저장은 기기·브라우저·사이트 주소별로 분리되며 브라우저 데이터 삭제 시 사라질 수 있습니다. JSON 파일을 내려받아 백업할 수 있습니다.

## 개선 과정

1. 설계 업무에 사용할 간단한 요구사항 메모에서 시작했습니다.
2. 사무·행정, 마케팅, 개발, 디자인·설계, 영업·고객응대, 매장 운영 예시로 확장했습니다.
3. 사용자의 피드백에 따라 예시와 실제 입력 항목을 동일하게 맞췄습니다.
4. “바꿔도 되는 부분”을 “구체적으로 해야 할 일”로 바꿨습니다. 할 일 목록과 진행 순서도 분리했습니다.
5. 이전 4번의 저장 내용은 새 의미로 재해석하지 않고 확인 질문으로 옮기도록 했습니다.

## 포트폴리오 설명

문제 정의와 사용자 피드백을 바탕으로 질문·정보 구조를 반복 개선한 프로젝트입니다. AI 도구를 활용해 구현과 문서화를 진행했습니다. 단순히 양식을 만드는 것을 넘어 예시와 입력 항목의 일치, 지시와 계획의 구분, 양식 변경 시 기존 데이터 보존을 고려했습니다.

실사용 성과나 재작업 감소율은 아직 측정하지 않았습니다. 기능 검증과 실제 사용자 효과는 구분합니다. 자세한 결정 배경과 한계는 [프로젝트 기록](docs/CASE_STUDY.md)을 참고하세요.

## 배포

GitHub Pages에 `dist/`를 배포하도록 `.github/workflows/pages.yml`을 구성했습니다. 저장소 Settings → Pages → Source에서 GitHub Actions를 선택한 뒤 배포 워크플로를 실행해야 처음 활성화됩니다. 활성화 후에는 `main`에 push할 때 검사 6개가 통과하면 자동 배포됩니다. 배포 성공 여부는 저장소 Actions에서 확인하세요. 유지보수 방법은 [저장소 운영 안내](docs/GITHUB.md)에 정리했습니다.
